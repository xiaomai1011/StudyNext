# StudyNext 功能实现方式清单

> 目的：把“真实可用、基本可用、只读、仅官方页面、已移除”的功能分开，作为重构与验收基线。
> 当前架构不是学习通官方 API 客户端，而是“用户本人 Web Session + 页面解析 + SQLite 缓存 + 原生 React UI”的混合实现。

## 一、基础架构

| 层       | 实现                                                                                                   | 关键文件                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| 会话     | Electron `WebContentsView` + `persist:studynext-portal` 持久分区，所有外部请求由主进程/Portal 会话发出 | `src/main/portal/service.ts`、`src/main/portal/security.ts`                               |
| 登录     | 用户在内嵌官方登录页完成账号密码/扫码；保存账号用 Windows DPAPI 加密；可选自动填表并点击官方登录按钮   | `src/main/integrations/chaoxing/credentials.ts`、`src/main/portal/autofill.ts`            |
| 数据读取 | 学习通页面 DOM/HTML 解析；跨域 iframe 通过 Portal 页面读取，不复制 Cookie 到默认 Session               | `src/main/integrations/chaoxing/adapter.ts`、`parsers.ts`、`session-client.ts`            |
| 数据存储 | SQLite（`node:sqlite`）保存课程、任务、章节、学习点、通知、资料、下载记录；含迁移与 `task_change_log`  | `src/main/storage/store.ts`、`src/main/storage/workspaces.ts`                             |
| 自动刷新 | `useSyncScheduler`：启动检查、前台 30 秒 tick、后台恢复、失败退避；同步由主进程串行执行                | `src/renderer/src/hooks/useSyncScheduler.ts`、`src/main/integrations/chaoxing/service.ts` |
| 提醒     | 进程内 `ReminderScheduler` + Windows Task Scheduler `--check-reminders` 无头检查                       | `src/main/notifications/*`                                                                |
| UI       | React 19 + Studio 设计 token；三顶层标签“今天/课程/作业”，页面内使用数据卡片、表格与覆盖层             | `src/renderer/src/App.tsx`、`src/renderer/src/pages/*`、`src/renderer/src/ui/studio.css`  |

## 二、功能矩阵

| 功能          | 现在的实现方法                                                                       | 真实程度                 | 主要限制                                                        |
| ------------- | ------------------------------------------------------------------------------------ | ------------------------ | --------------------------------------------------------------- |
| 学习通登录    | 内嵌官方登录页；保存账号自动填表并点击官方登录按钮；验证码/MFA 交给用户              | 真实可用                 | 会话过期、页面跳转、头像加载受平台影响；切换账号需重新登录      |
| 多账号        | DPAPI 保存多个账号；账号菜单切换 active；每账号独立 SQLite 工作区                    | 真实可用                 | 切换用户需要重新登录；身份显示依赖平台 UID                      |
| 课程列表      | 解析 Portal 已渲染课程卡（courseid/clazzid/cpi）                                     | 真实可用                 | 依赖页面 DOM；封面/学期/教学班字段可能不完整                    |
| 任务/DDL      | 解析作业列表与详情；六态平台状态与本地状态分离；SQLite 去重 upsert；保留 `sourceUrl` | 真实可用                 | 详情页部分字段缺失；提交时间常为 null；平台改版会导致解析失败   |
| 任务中心      | 原生列表、状态筛选、逾期/待审核/已完成分组、行点击详情                               | 基本可用                 | 筛选与状态文案仍需持续统一                                      |
| 课程工作台    | 章节、小节、学习点与资料统一在课程空间；跨课程搜索与章节定位                         | 真实可用                 | 平台 `0/0` 任务点课程只能浏览，不显示虚构进度                   |
| 学习点/进度   | 只在平台有真实任务点时生成学习点；进度来自平台 `已完成任务点 n/total`                | 真实可用                 | 依赖页面标记；无任务点课程明确提示“仅供浏览”                    |
| 作业附件上传  | 官方作业页 UEditor + WebUploader；应用内登录态使用官方上传控件                       | 真实可用（用户本人操作） | 不是原生上传组件；上传状态来自 webRequest 事件，不是逐字节进度  |
| 作业草稿      | 官方作业页“暂时保存”调用 `addStudentWorkNewWeb`                                      | 真实可用                 | 只能在官方页面操作，应用无原生草稿模型                          |
| 作业提交      | 不代点；用户在官方页面确认提交；监听提交成功跳转/请求后重新同步                      | 真实可用（用户本人操作） | 提交结果依赖官方页面；成绩/批语回填依赖详情页解析               |
| 作业记录      | 解析作业详情的成绩、满分、教师批语、附件；本地筛选与详情                             | 真实可用                 | 提交时间缺失；附件归属不明确；批语解析可能截断                  |
| 资料中心      | 解析资料 iframe；按课程合并教学班并去重；课程颜色区分                                | 基本可用                 | 文件夹节点未完整建模；分页只做部分支持；部分大小字段为空        |
| 资料下载      | 主进程 `net.request` + Portal Session 流式下载；下载历史、取消、重试、再次下载       | 真实可用                 | 依赖学习通 CDN 重定向；失败原因未持久化；网络中断恢复需继续验证 |
| 考试中心      | 解析考试列表页表格，只读展示                                                         | 只读                     | 无原生考试作答；状态/时间字段解析不稳定                         |
| 通知          | Portal 内读取通知列表，最多 3 页；课程上下文跳转                                     | 只读                     | 无通知已读同步、分类管理或主动推送                              |
| 周课表/日历   | 解析课表页；首页五时段周表；周/日/月/时间轴视图                                      | 基本可用                 | 依赖课表页结构；单双周、调休、多教师等复杂情况未完整建模        |
| 自动刷新      | 集中式 hook：启动、前台 tick、后台恢复、失败退避；间隔 3/5/10/15 分钟或关闭          | 基本可用                 | 同步与 Portal 共用页面，可能引起页面跳动；全量同步耗时较长      |
| 搜索/命令面板 | 原生全局搜索与 `Ctrl+K` 命令面板                                                     | 真实可用                 | 部分结果定位仍需接线；搜索范围受本地数据限制                    |
| 设置页        | 外观、应用行为、DDL 提醒、学习通与同步、手动导入、数据与关于                         | 真实可用                 | 历史文案已清理，后续仍随功能变化更新                            |
| 系统级提醒    | Task Scheduler 当前用户任务 + `--check-reminders` 无头检查 + 失败重试                | 已实现，待发布级验证     | 安装/升级/卸载、定时触发、多用户/睡眠/SQLite 锁未完整验收       |
| 导入          | CSV/ICS/JSON 快照手动导入                                                            | 真实可用                 | 不主动拉取、不自动刷新、不冒充实时同步                          |
| AI 解题       | 已移除                                                                               | 已移除                   | 旧库 `questions`/`ai_config` 仅只读迁移兼容，禁止恢复入口       |

## 三、结论

- **真正稳定的是数据读取与存储层**：课程、任务、章节、学习点、通知、资料、下载有真实数据和 SQLite 持久化。
- **真正原生的操作很少**：作业编辑、附件上传、草稿、提交仍依赖官方页面；资料下载与本地预览是原生；账号登录是内嵌官方页。
- **当前最大风险不是功能数量，而是页面解析与平台行为漂移**：同一功能一半在原生 UI、一半在官方页面；同步会改变 Portal 页面；账号/登录/头像状态需要持续校准。
- **后续优先级**：先保证数据正确性、同步状态诚实、官方页面入口正确，再扩展功能；不为了页面数量牺牲可维护性。

## 四、维护规则

- 新增功能必须在本表标明真实程度与限制，不能只写“已实现”。
- 真实账号验证必须标注日期与验证范围；未验证项写入 [STATUS.md](STATUS.md) 的待办。
- 功能下线后同步删除本表条目，并在 [CHANGELOG.md](CHANGELOG.md) 记录。

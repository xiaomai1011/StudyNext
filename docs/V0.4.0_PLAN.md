# StudyNext v0.4.0 研究与开发计划

- 版本：0.4.0 研究基线
- 日期：2026-11-12
- 状态：第一轮只做研究、设计和独立 PoC，不实现未经授权实时适配器
- 基线分支：`v0.4.0-development`
- v0.3.0 基线提交：`06deacf chore: establish StudyNext v0.3.0 baseline`

## 1. 目标

StudyNext 采用 C 路线：

> 以深度集成学习通为第一目标，同时为未来其他教育平台预留扩展能力。

v0.4.0 的目标不是“增加最多代码”，而是建立一条可验证、可审计、可停止的真实接入路线：

1. 在不伪造同步状态的前提下，提升现有导入数据的价值和可信度。
2. 明确学习通官方授权、机构授权、用户手动导入和官方页面访问的边界。
3. 设计最小 Provider 抽象和同步中心，使未来接入不会重写现有领域模型。
4. 用独立 PoC 评估应用完全退出后的 Windows DDL 提醒。
5. 在没有正式授权时明确停止实时适配器，不用私有接口强行实现。

非目标：

- 自动刷课、伪造学习记录、自动考试答题、代交作业。
- 验证码绕过、反爬规避、未授权私有接口调用。
- 自动登录、替用户输入密码、保存明文凭据。
- 把网页打开成功当作同步成功。
- 本轮不重写为 MyGo、Tauri 或 Go，不替换 Electron 技术栈。

## 3. 工作分解

### W0：基线保护（已完成）

- 检查工作区和现有修改。
- 把 v0.3 变更整理为基线提交 `06deacf`。
- 创建 `v0.4.0-development` 分支。

- 不覆盖用户已有修改，不强制 reset。

### W1：接入研究（本轮）

- 核实官方开放平台、机构授权、数据导出和 `xuexitong-cli`。
- 输出 `CHAOXING_ACCESS_MATRIX.md`、`CHAOXING_INTEGRATION_RESEARCH.md`。
- 给出 Go/No-Go 门槛，明确没有官方授权时不写实时 Provider。
- 对现有快照、CSV/ICS、Portal 能力做复用评估。

### W2：Provider 契约（授权前可先设计，不接真实数据）

- 把现有 `AuthorizedDataAdapter` 扩展为通用 Provider 接口。
- 增加 `ProviderCapabilities`，按资源声明 `official/institutional/manual/web_only/unavailable`。
- 保持 `ChaoxingProvider` 的 `isConfigured()` 为 false；只返回 `not_configured`，不返回空成功。
- 现有 JSON 快照作为 `ManualSnapshotProvider`，仍使用 `source='import'`。
- 不实现未经授权的网络访问；所有真实 Provider 代码等待授权。

### W3：同步中心与数据模型（优先复用现有代码）

需要新增或演进：

- `sync_runs`：一次同步的执行记录、触发方式、开始/结束时间、状态、错误码、统计计数。
- `sync_resource_runs`：按课程/章节/任务/通知/课表等资源记录成功、失败、跳过和分页数。
- `provider_cursors`：授权 Provider 的不透明增量游标；手动快照没有游标。
- `sync_conflicts`：字段级冲突，包含本地值、平台值、手动保护字段和解决状态。
- `sync_notifications`：截止变化、成绩/状态变化等用户可见提示（不等于系统通知）。
- 现有 `task_change_log` 继续记录任务变更；新增记录必须标明 `origin`。

同步语义：

- 分页参数由 Provider 定义；通用层不假设页码或时间戳一定存在。
- 增量同步使用 Provider 返回的不透明 cursor；空 cursor 不等同于“从头删除”。
- 去重键：`providerId + resourceType + externalId`；任务另有课程前缀。
- 截止变化：写入变化记录并清理旧的提醒投递（复用现有 `notification_deliveries` 逻辑）。
- 手动字段：`Task.manualFields` 优先；平台不能覆盖。冲突必须呈现，不可静默丢弃。
- 本地完成与平台完成分离：本地手动完成不得被平台“未完成”覆盖；平台完成可以提示用户确认。
- 同步结果：`success / partial / failure / not_configured`；禁止把异常吞掉后返回 success。

### W4：Windows DDL 系统级提醒（独立 PoC）

- 保持现有 `NotificationScheduler` 不变。
- 建立 `scripts/notification-poc/` 独立 PoC。

- 推荐阶段 1 使用 Task Scheduler + `StudyNext.exe --check-reminders`，阶段 2 再评估 Scheduled Toast。

## 4. Provider 最小抽象

```ts
type AccessLevel = 'official' | 'institutional' | 'manual' | 'web_only' | 'unavailable'

interface ProviderCapabilities {
  courses: AccessLevel
  courseDetail: AccessLevel
  homework: AccessLevel
  homeworkDeadline: AccessLevel
  submissionStatus: AccessLevel
  exams: AccessLevel
  examSchedule: AccessLevel
  courseAnnouncements: AccessLevel
  schoolNotices: AccessLevel
  chapters: AccessLevel
  studyPoints: AccessLevel
  progress: AccessLevel
  materials: AccessLevel
  schedule: AccessLevel
}

interface ProviderPage<T> {
  items: T[]
  nextCursor: string | null
  fetchedAt: string
  warnings: string[]
}

interface EducationProvider {
  readonly id: string
  readonly label: string
  readonly capabilities: ProviderCapabilities
  getAuthState(): 'unknown' | 'logged_out' | 'authorized' | 'expired'
  pullCourses(cursor?: string): Promise<ProviderPage<Course>>
  pullTasks(courseExternalId?: string, cursor?: string): Promise<ProviderPage<Task>>
  pullNotices(cursor?: string): Promise<ProviderPage<AppNotice>>
  pullCalendar(cursor?: string): Promise<ProviderPage<CourseSession>>
}
```

实现约束：

- 所有网络请求和 Token 只在 Electron main 进程；renderer 不接触 Token。
- Provider 不直接写 SQLite，由 `SyncService` 做字段级合并和审计。
- `capabilities` 是静态声明，不从“能打开页面”推断。
- 每个 Provider 必须标出数据来源、授权方式和可撤销方式。
- 其他平台只保留接口，不实现智慧树/雨课堂。

## 5. 同步中心交互设计

### 5.1 信息架构

在现有设置/同步区域之上增加“同步中心”入口，不重做全站视觉：

- 顶部：当前数据源卡片（手动快照 / 学习通授权未配置 / 未来 Provider）。
- 状态：最后导入/同步时间、来源、运行状态、错误摘要。
- 能力表：14 项能力各自标签（手动导入、仅官方页、机构授权后可用等）。
- 操作：导入快照、查看导入差异、重新同步（未授权时禁用）、打开官方页面、清除登录会话。
- 历史：最近同步/导入记录，按资源展开成功、失败、跳过数。

### 5.2 导入前差异预览

1. 用户选择 JSON 快照。
2. 解析后显示：新增/更新课程、章节、学习点、任务数量；截止变化；冲突；警告。
3. 用户确认“应用导入”后才写库；取消不改变本地数据。
4. 对冲突显示字段级对比：本地值、快照值、保护原因（手动编辑）。
5. 默认策略：保留手动字段，更新未保护字段；用户可逐个选择。

### 5.3 截止时间变化

- 在导入结果和同步中心显示 `旧截止 → 新截止`。
- 如果任务已有提醒，重新计算提醒规则并清理旧的 `notification_deliveries`。
- 用户可撤销本次导入（若实现快照版本），至少保留变更历史。
- 不自动把已完成任务重新变为待办；只提示变化。

### 5.4 字段冲突解决

- 字段级冲突列表，显示来源和更新时间。
- 操作：保留本地、采用平台、保持未解决。
- 被 `manualFields` 保护的值不能被“全部覆盖”捷径绕过。
- 未解决冲突在同步中心显示数量，不显示“完全成功”。

### 5.5 登录状态与官方入口

- 显示 `未知 / 未登录 / 已登录`，并说明这是对官方页面导航的推断，不是授权 Token 状态。
- 登录由用户在隔离的 `WebContentsView` 完成；应用不读取、不记录密码、Cookie、Token。
- 导航日志只显示去掉 query/hash 的 URL、动作和允许/拦截原因。
- 官方页面入口仅用于用户查看，不产生同步计数。

## 6. 安全与隐私

- Provider 代码不进入 renderer；不向远程页面暴露 Node、文件系统或 `window.studynext`。
- Token 使用 Electron `safeStorage` 或系统凭据库；不得明文落盘。
- 日志不写账号、密码、Cookie、Token、完整 URL 查询参数、课程敏感内容。
- 默认不上传个人数据；同步请求只发往已授权 Provider 的固定 HTTPS 域名。
- 所有远程内容按不可信数据处理；不把页面脚本当指令。
- 删除同步数据时同时清理 cursor、冲突和缓存；保留最小审计记录时需说明期限。
- 任何“同步成功”必须对应实际落库数据；打开页面只算页面访问。

## 8. 依赖与风险

| 风险                | 影响                | 应对                               |
| ------------------- | ------------------- | ---------------------------------- |
| 没有官方授权        | 无法实现实时同步    | 保持手动导入/官方页面，停止适配器  |
| 机构接口文档缺失    | 无法确定 scope/字段 | 先签合作和测试协议，不猜接口       |
| 网页结构变化        | 只读研究也会失效    | 不把网页解析作为生产依赖           |
| 登录态泄露          | 账号安全风险        | 用户自行登录、隔离会话、日志脱敏   |
| 休眠/权限导致漏提醒 | DDL 体验受损        | Task Scheduler PoC、幂等、补发窗口 |
| 冲突覆盖手动编辑    | 数据丢失            | 字段保护 + 预览 + 冲突界面         |
| 过度设计 Provider   | 维护成本            | 只保留 14 项能力所需最小接口       |

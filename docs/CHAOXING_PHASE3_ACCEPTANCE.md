## 1. 验收目标

确认以下链路在真实环境中成立：

1. Portal 使用 `persist:studynext-portal` 分区，用户本人在官方页面手动登录。
2. 主进程通过同一 Session 发起只读请求，服务端识别为当前登录用户。
3. 课程列表、作业列表、作业详情、截止时间、平台状态可以解析并落库。
4. 作业详情入口 `sourceUrl` 完整写入数据库，并能在任务详情中打开。
5. 登录过期、验证码/安全验证、网络失败时停止自动请求，且不破坏本地已有数据。

## 2. 前置条件

- [ ] 使用 `v0.4.0-development` 工作区构建的应用，未修改 `persist:studynext-portal` 分区名。
- [ ] 用户本人在 Portal 打开 `https://i.chaoxing.com/base` 并完成登录（含学校/机构选择）。
- [ ] 登录过程没有出现验证码、滑块或 MFA；如出现，由用户本人处理，应用不做绕过。
- [ ] 至少有一个学期内、包含作业的课程；记录课程名与教学班。
- [ ] 准备一份不包含 Cookie、Token、完整敏感 URL 的截图/录屏目录。

## 6. 已知限制（验收时重点观察）

1. 课程列表可能位于跨域 `#frame_content` iframe；主进程 HTTP 读取 `/base` 外层 HTML 时可能拿不到课程卡片，此时应报解析错误，而不是伪造空列表。
2. `enc/openc/workEnc/stuenc` 是按课程、按学生生成的动态签名，过期后作业页会返回“没有此页面访问权限”。
3. 每门课最多读取 20 份作业详情，作业很多时部分截止时间会显示“待确认”。
4. 作业列表分页尚未处理，只读取当前页。
5. 未知截止时间使用内部哨兵值存储，UI、提醒与日历已过滤；导出或其他新消费者需要继续遵守该约定。

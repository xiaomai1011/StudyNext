# StudyNext v0.4.0 Go / No-Go 评估

- 版本：0.4.0 研究基线
- 日期：2026-11-12
- 决策对象：是否在 v0.4.0 实现学习通实时数据适配器
- 结论：**有条件 No-Go（停止实时适配器开发），继续做可离线验证的 Provider 契约、同步中心设计和 Windows 通知 PoC。**

## 1. 一句话结论

目前没有可核验的官方 OAuth、机构接口文档或测试账号，不能把 `xuexitong-cli` 的网页 Cookie/HTML 解析路径接进产品。v0.4.0 应继续做用户主动导入和官方页面兼容，不启动实时 `ChaoxingProvider`。

## 2. 决策表

| 事项                            | 决策                  | 理由                                                    |
| ------------------------------- | --------------------- | ------------------------------------------------------- |
| 官方 OAuth / 数据 API           | **No-Go**             | 公开入口只有登录跳转，没有 scope、注册、文档或测试环境  |
| 个人开发者接入                  | **No-Go**             | 未发现可申请入口，不能把登录页当授权                    |
| 学校机构授权                    | **Conditional Go**    | 现实中可能，但必须先拿到书面授权、接口清单、测试账号    |
| 使用 xuexitong-cli 私有网页接口 | **No-Go（生产）**     | 依赖 Cookie/HTML/隐藏字段，未经授权且有风控和稳定性风险 |
| 用户主动 JSON/CSV/ICS 导入      | **Go**                | 已有实现、可验证、不会冒充实时同步                      |
| 官方页面兼容入口                | **Go**                | WebContentsView 隔离，用户自行登录，不抓取页面          |
| Provider 契约与能力矩阵         | **Go**                | 不访问外部数据，为未来授权做准备                        |
| 同步中心/差异预览/冲突设计      | **Go**                | 先做交互和模型，不接未授权数据                          |
| Windows 通知 PoC                | **Go**                | 独立脚本，不替换现有 scheduler                          |
| 后台常驻服务                    | **No-Go（第一阶段）** | 安装/权限/会话通知成本过高                              |
| 自动刷课/考试答题/验证码绕过    | **永久 No-Go**        | 明确排除，不属于产品能力                                |

## 3. 实时适配器的硬门槛

只有以下证据全部齐备，才能把状态从 No-Go 改为 Conditional Go：

- [ ] 超星或学校的书面接入许可，含应用名称和开发者主体。
- [ ] 正式认证方式：OAuth 2.0 或机构等价方案，附 client 注册流程。
- [ ] 课程、章节、作业、考试、通知、课表、资料的 scope 清单。
- [ ] 字段字典、分页规则、增量 cursor、错误码和限流/退避要求。
- [ ] 测试学校、测试账号和可重复的验收脚本。
- [ ] Token 生命周期（有效期、刷新、撤销）和审计要求。
- [ ] 数据保留、删除、隐私影响评估和日志脱敏要求。
- [ ] 明确的 UI/品牌规范（如第三方客户端标识要求）。
- [ ] 安全评审通过：main 进程持有 Token、renderer 无凭据、无敏感日志。
- [ ] 真实账号回归通过：登录、过期、撤销、断网、限流、部分成功、冲突。

任何一项缺失，都继续使用手动导入和官方页面，不得用私有接口补洞。

## 4. 当前可交付范围（Go）

### 4.1 数据能力

- 手动 JSON 快照：课程、章节、学习点、作业、考试、课表。
- CSV/ICS：任务和日历的离线导入。
- 任务 CRUD、DDL 排序、提醒、日历。
- 快照字段冲突保护、截止变化检测、本地/平台完成状态分离。
- 同步中心和导入差异预览的交互设计（本轮为设计文档）。

### 4.2 安全能力

- WebContentsView 隔离、URL 白名单、危险跳转拦截、下载阻止。
- 登录状态仅作为官方页面导航推断，不读取凭据。
- 导航日志脱敏，日志不写 query/hash。
- SSO 域名可配置，只允许 HTTPS 443、无 userinfo 的精确域/子域。

### 4.3 Windows 通知

- 独立 PoC 验证 Task Scheduler 的注册/运行/清理。
- 独立 PoC 验证 Scheduled Toast 的注册/移除。
- 推荐先做 Task Scheduler + `--check-reminders`，不立即替换现有 scheduler。

## 5. 明确 No-Go 的功能

- 未经授权的学习通私有接口。
- 自动登录、代填密码、验证码绕过。
- 自动刷课、伪造学习记录、自动签到。
- 自动考试答题、代交作业。
- 通过解析官方网页批量提取课程/作业数据。
- 把导入/模拟数据标记为实时同步。
- 在日志中记录密码、Cookie、Token 或完整敏感 URL。
- 未签名安装器直接注册系统级通知身份并宣称稳定可用。

## 6. 风险与停止条件

| 风险           | 触发条件                       | 停止/回退                                     |
| -------------- | ------------------------------ | --------------------------------------------- |
| 官方接口不可得 | 无书面授权、无文档             | 停止实时适配器，保留手动导入                  |
| 接口不稳定     | 网页结构变化、频繁 9010/验证码 | 不再依赖该来源，回退官方页面                  |
| Token 安全事件 | 日志/缓存出现凭据              | 立即停止同步、清除 Token、审计                |
| 字段覆盖       | 手动字段被平台覆盖             | 停止自动应用，要求冲突解决                    |
| 通知双发       | 同一 dueAt 多条投递            | 以 `notification_deliveries` 为准，禁用触发器 |
| 安装/卸载残留  | 计划任务/AUMID/Token 未清理    | 阻止发布，补卸载脚本                          |

## 7. 推荐决策

**v0.4.0 第一轮：Go（研究、Provider 契约、同步中心设计、Windows PoC）；实时适配器：No-Go。**

下一轮只有在硬门槛至少完成 1–5 项后，才进入 `ChaoxingProvider` 的 spike；spike 也必须使用测试账号、只读数据、可一键关闭，不得进入生产打包。
